## 0. 一句话结论

**协议/算法链已通**（mtgsig 签名 + `z()` 参数 + 原生 `wx.login` code 获取 + `getWxIds` 全过），
**业务闭环卡在美团行为风控**：`silentLogin` 的 `wechatFingerprint` 要求来自真实微信客户端环境，
静态/随机指纹会被判 `101144 user_has_risk`（或长 base64 体被 openresty WAF 直接 403）。

## 1. 登录链路

对应小程序 `copy/account/account-core` 的 `silentLogin(e)`：

```
silentLogin(e):
  url = netCheck ? newwxsilentlogin : wxslientlogin   # 两个不同 path
  Promise.all([ $(), ce() ]).then([fp, code])          # $()=finger.g(), ce()=wx.login()
    G({url, header: pe, data: {wechatFingerprint: fp, code: code, (token 已登录时)}})
    -> {openId, unionId, openIdCipher, unionIdCipher, data:{userId, token}, error}
```

| 步骤 | 方法 | Path | 请求 | 返回 |
|---|---|---|---|---|
| getWxIds (`de`) | POST(form) | `/user/thirdinfo/getweappuserinfo` | `{code, appName}` | `{openid, openidCipher, unionid[, unionIdCipher]}` |
| silentLogin (`ye.silentLogin`) | POST(form) | `/user/v1/weappsilentlogin` | `{wechatFingerprint, code[, token]}` | `{openId, unionId, openIdCipher, unionIdCipher, data:{userId, token}}` |
| newwxSilentLogin (netCheck) | POST(form) | `/user/v1/weappsilentloginembedded` | 同上 | 同上 |
| getMtInfo (`ge`) | GET | `/user/v1/info` | `?token=&fields=id,username,avatarurl,...` | `{user:{id, username, ...}}` |

请求包装 `z()` 追加 query（仅非空值）：
`sdkVersion, utm_medium, joinkey, sdkType=wxmp, login_sdk_version, appName,
risk_app, risk_partner, risk_platform, risk_smsPrefixId, risk_smsTemplateId,
version_name, token_id, uuid`；
data 合并 `device_type`(=model) / `device_os`=`微信小程序`；
再经 `jsguard.sign` 注入 `header.mtgsig`。

## 2. code 从哪来（关键）

真机里 `ce()` 调 `wx.login()` 拿 code，**单次有效**。纯协议环境没有微信客户端，
用 **YYB(应用宝电脑版) 微信会话** 铸出**同款原生 wx.login code**：

```
pcyyb SessionStore.load(account)      # 扫码登录态 (unionid/at/guid)
  -> authorize_buffer()['raw']         # 微信平台授权 buffer
  -> qqfarm.getNativeWxLoginCode(buf, app_id)   # MMTLS + ShortLink 铸码
  -> code                              # 可被 getweappuserinfo / weappsilentlogin 接受
```

> 注意: `pcyyb.authorize_code()` 返回的 `login_code` **不是** wx.login code，
> 喂给 `getweappuserinfo` 会得 `101172 invalid code`。必须走 MMTLS 铸码。

本项目封装见 `src/meituan_waimai/yyb_code.py`（`get_wx_login_code` / `try_get_wx_login_code`）。

### 2.1 authorize_buffer 的两种失效（scope vs credential）

`authorize_buffer`（即 `[B] pcyyb_get_wx_login_buffer_auth`）是整条 MMTLS 铸码
路径的**总开关**。它只有两种失效码，语义完全不同：

| code / msg | 含义 | 触发条件 | 恢复方式 |
|---|---|---|---|
| `-101 [40188 invalid scope]` | AT **有效**，但该授权的 granted scope **不含** `snsapi_runtime_pcsdk` | 扫码授权集合被覆盖 | **重新扫码**（`scope=snsapi_login,snsapi_runtime_pcsdk`） |
| `-101 [40001 invalid credential, ... not latest]` | AT **本身失效** / 被顶替（非最新） | AT 过期或同 openid 被新登录顶替 | **重新扫码** |

**掉 scope 的根因（实测 + 反编译交叉验证，2026-10-11）**：

`snsapi_runtime_pcsdk` 不是 access_token 的固有属性，而是**扫码授权那一刻按 `scope=`
参数授予、记录在微信侧 `(appid, openid)` 维度**的授权集合。当该微信号在**其它入口**
（真机微信 / 另一个应用宝实例）以**更弱的 scope**（仅 `snsapi_login`）重新授权同一个
`appid=wxd44977328b36e647` 时，微信侧该 `(appid, openid)` 的 scope 快照被**覆盖**，
于是我们持有的 AT 虽然仍然有效（`api.weixin.qq.com/sns/userinfo` 正常返回），
`authorize_buffer` 却报 `40188 invalid scope`。

这也解释了**为什么 refresh / check_login 不能恢复**：它们只**延续** AT（微信侧
`sns/oauth2/refresh_token` 实测返回的是**同一个** AT，`scope` 字段仍是
`snsapi_login,snsapi_runtime_pcsdk`），并不重新走授权流程，因此无法重建被覆盖的 scope
快照。**唯一恢复手段是重新扫码登录**。

> 排除实验（同一可用登录态，实测均**不掉** scope，`authorize_buffer` 始终 OK）：
> `refresh(v1 pc_yyb)`、`refresh(v3 pc_yyb_auth)`、`check_login`、MMTLS 多次铸码、
> `[A] authorize_code`（含白名单/非白名单 appid）。故「refresh 丢 scope」的旧假设**不成立**。

## 3. 生产实测（2026-10-11）

环境: pcyyb 账号 `清歌不尽` (unionid `oTOwy6QWDRrpteehjeRYPXyOoVUs`)，
真机参数 `platform=windows, model=PC, wx_version=3.9.12`。

| 步骤 | 结果 |
|---|---|
| pcyyb 铸原生 code | ✅ |
| `getWxIds` | ✅ HTTP 200，拿到 `openId=oOpUI0bNdjVqpdzCf0qXvsuAQD3w` / `unionId=oNQu9t2VIrizO07W_ENbjX1-0teU` / `openIdCipher` |
| `silentLogin` (短占位指纹 `WX__ver1.2.0_TEST`, 17B) | ✅ **HTTP 200，返回真实 token + `userId=2665956845`** |
| `silentLogin` (随后连续多次) | ❌ HTTP 200 + `{"code":101144,"type":"user_has_risk","message":"当前行为异常，请使用APP操作"}` |
| `silentLogin` (随机 base64 指纹 240B / 生成器全量 254B) | ❌ HTTP 403 (openresty WAF 拦截请求体) |

### 3.1 指纹长度矩阵实测（两个分支都测，2026-10-11）

对 `weappsilentlogin`（`wxslientlogin`）与 `weappsilentloginembedded`（`newwxsilentlogin`，
netCheck 分支）分别用同一批指纹各打一次：

| wechatFingerprint | 长度 | `weappsilentlogin` | `weappsilentloginembedded` |
|---|---|---|---|
| 短占位 `WX__ver1.2.0_TEST` | 17B | ✅ HTTP 200，`token=True` | ✅ HTTP 200，`token=True` |
| 随机 base64 | 240B | ❌ HTTP 403 | ❌ HTTP 403 |
| 纯 Python 生成器 `finger.g()` 全量 | 254B | ❌ HTTP 403 | ❌ HTTP 403 |

**结论**：

- **短指纹在「两个」silentLogin 分支都能过 WAF 并拿到真实 token**——`silentLogin` 的
  协议层（`z()` + mtgsig 签名 + code）**完全正确**，卡点纯粹是**请求体长度触发 openresty WAF**。
- WAF 是**体长阈值**判定（≥~78B 的 base64 指纹直接 403），与指纹内容无关；真机指纹
  之所以能过，是因为它走的是**微信客户端内嵌请求**（非 openresty 直连），不经过这层 WAF。
- 连续用短指纹调用仍会被 `101144 user_has_risk` 行为风控拦截，说明 WAF 之后还有一层
  **行为频率 + 设备指纹**判定。

### 关键判断

1. **签名正确**：`getWxIds` 用同一套 `z()`+mtgsig 稳定成功，证明签名/参数无误。
2. **code 正确**：YYB 铸的原生 code 被 `getWxIds` 接受。
3. **`silentLogin` 协议层正确**：短指纹在两个分支都 200 返回真实 token（见 §3.1），
   证明 `z()`+mtgsig+code 全对。
4. **卡点分两层**：
   - **WAF 层**：长 base64 指纹（≥~78B）直接 403（openresty 体长拦截）；
   - **业务风控层**：WAF 放行后，连续调用被 `101144 user_has_risk`（行为频率 + 设备指纹）拦截。
5. 结论：美团把该接口的风控绑在**真实微信客户端环境**上，纯协议下**短指纹首次可过、持续调用会被封**。

## 4. 错误码速查

| code / HTTP | type | 含义 |
|---|---|---|
| `101172` | `weapp_invalid_session` | code 无效/已用（`login_code` 或过期 code） |
| `101144` | `user_has_risk` | **行为风控**（非签名问题） |
| HTTP 403 | openresty | WAF 拦截请求体（长 base64 指纹等） |
